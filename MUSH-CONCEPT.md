## 1. Почему MUSH

Mycerus — это инфраструктура: грибница из проводов, протоколов и иммунной системы. Для инженера это красиво. Для человека с телефоном — это "плесень".

**MUSH** — это то, что растёт на грибнице: простой, сочный, понятный плод. Пользователь не знает про DTN, BPv7, Vironet или Immune Block. Он знает, что открыл приложение, написал сообщение, и оно дошло — даже если сейчас нет интернета, даже если собеседник в другом конце города, даже если кто-то глушит связь.

**Три столпа:**
1. **Простой** — как Telegram, но без сервера.
2. **Надёжный** — как почта, но быстрее.
3. **Конфиденциальный** — как личная встреча, но на расстоянии (в пределах того, что даёт текущая сеть — см. §5.3 и §6).

**Плодовые тела (MUSH Client)** — телефоны, ноутбуки, планшеты. Они:
- Генерируют ключи (Ed25519) при первом запуске.
- Шифруют сообщения E2E перед отправкой.
- Подключаются к ближайшим узлам Mycerus через WiFi-Direct, BLE или LAN.
- Могут работать в режиме "только я" (consumption) или "я + relay" (добровольно раздают чужие сообщения).

**Грибница (Mycerus Mesh)** — статичные узлы: роутеры, одноплатники, WiFi-точки. Они:
- Формируют постоянную mesh-инфраструктуру.
- Хранят и пересылают bundle'ы (store-carry-forward).
- Выполняют маршрутизацию (MGR), аутентификацию узлов (SNS, challenge-response — ТЗ §9) и иммунную защиту.
- Могут иметь bridge в интернет (опционально).

## 3. Пользовательский опыт (UX)

### 3.1. Первый запуск (30 секунд)

1. **Скачивание** — App Store, F-Droid, или ссылка от друга.
2. **Splash screen** — логотип MUSH (ягода + мицелий).
3. **Генерация ключа** — "Создаём ваш защищённый ключ..." (2 секунды, Ed25519). Нет телефона, нет email, нет SMS.
4. **Имя и аватар** — отображаемое имя + автоматический идентикон на основе pubkey.
5. **Готово** — можно сразу получать invite или показать QR.

**Ключ — это ты.** Нет учётной записи, которую можно взломать. Нет сервера, который может утечь.

### 3.2. Добавление контакта

**Основной поток (invite-link):**

```
Алиса → "Поделиться контактом" → генерирует invite-link
        ↓
https://mush.app/i#pubkey=abc123&nonce=xyz789
        ↓
Боб кликает ссылку → открывается страница → скачивает приложение
        ↓
Приложение автоматически подхватывает pubkey Алисы + nonce
        ↓
SBP-handshake → контакт добавлен. Один клик, ноль ручного ввода.
```

Invite-link содержит:
- URL для скачивания (универсальная ссылка на APK / TestFlight / F-Droid)
- Pubkey приглашающего
- Ephemeral nonce для SBP-handshake

**Терминология:** SNS-handshake — это аутентификация **узлов** сети Mycerus (challenge-response по Ed25519, ТЗ §9). Handshake **людей** (добавление контакта в мессенджере) называем **SBP-handshake** (Spore Bundle Protocol, см. MUSH-ARCH §2.2). Это разные уровни.

**Fallback для офлайн (QR / NFC):**

| Способ | Когда | Как работает |
|--------|-------|-------------|
| **QR-код** | Нет интернета, нельзя кликнуть ссылку | Алиса показывает QR с pubkey. Боб сканирует. SBP-handshake для подтверждения. |
| **NFC** | Телефоны рядом | Касаются → ключи передаются → SBP-handshake автоматически. |
| **Ретрансляция** | Есть общий контакт | Общий контакт C передаёт pubkey A к B (encrypted). B получает ключ, но **не может отправить сообщение** — нужен SBP-handshake с A. |

**Конфиденциальность:** публичный ключ не раскрывает личность. Никакого центрального каталога. Invite-link — это не публичный профиль, это одноразовый токен.

### 3.3. Чат

```
┌─────────────────────────────┐
│  ◀  Алиса        [⋯] [⚡]  │  ← имя контакта, статус сети
├─────────────────────────────┤
│                             │
│  Привет, как дела?          │  ← сообщение отправлено
│            ✓✓  14:32        │     ✓ = принято сетью Mycerus
│                             │     ✓✓ = получатель скачал bundle
│                             │          (подписанный ReportE2EDelivery,
│                             │           MGR-API-SPEC §4.12)
│  Я в районе моста, связи    │  ← сообщение в пути
│  почти нет                  │     часы = ждём маршрут
│            ⏳               │
│                             │
│                Всё ок!      │  ← входящее
│                ✓✓  15:45    │
│                             │
├─────────────────────────────┤
│  [📎]  [🎤]  Написать... [▶]│
└─────────────────────────────┘
```

**Статусы сообщения (честные — см. §10):**
- `✓` — сообщение принято сетью Mycerus (есть хотя бы 1 путь).
- `✓✓` — сообщение доставлено узлу или custodian'у получателя; его устройство скачало bundle. Подтверждается **подписанным** ReportE2EDelivery (MGR-API-SPEC §4.12). Это **не** «прочитано человеком».
- `⏳` — сообщение ожидает пути (нет контактов, но оно хранится и будет отправлено, пока не истечёт TTL).
- `⚠️` — сеть подозревает атаку на маршрут (Immune plane сработал), возможна задержка. Ложные срабатывания возможны: критерий этапа 19 — ложные тревоги < 5% без атаки (ТЗ, этап 19).

**Никаких "онлайн" статусов.** В DTN понятие "онлайн" не имеет смысла. Вместо этого:
- "Был в сети X минут назад" (по последнему контакту).
- "Рядом N узлов" (сколько Mycerus-узлов видит ваш телефон прямо сейчас).

### 3.4. Сеть

Вкладка "Сеть" показывает абстрактную визуализацию:
```
        [🍄]           ← вы
       /  |  \
    [📡] [📡] [📱]     ← 3 узла в радиусе (2 роутера, 1 телефон)
      \   |   /
       [🌐]           ← internet bridge (опционально)

Сеть: 12 узлов видно
Путь к Алисе: 3 прыжка
Сообщения в очереди: 2
```

Это **не карта с координатами** — это абстрактный граф. Никакой геолокации, никакого отслеживания.

### 3.5. Групповые чаты — сервер-грибница (Fruiting Gateway)

В MUSH нет "общего чата в воздухе". Хочешь канал — поднимай свою грибницу.

**Как это работает:**
- Создатель поднимает **Fruiting Gateway** — выделенный узел Mycerus (может быть на телефоне, роутере, Raspberry Pi).
- Грибница-хост хранит историю канала, relay'ит сообщения участникам.
- Участники синхронизируются при контакте с грибницей (store-carry-forward).
- Создатель модерирует relay, но не может подделать историю — сообщения подписаны отправителями.

**Приглашение:**
- Создатель отправляет invite (QR или через контакт).
- Участник **явно принимает** (accept) — без согласия нет подписки.
- Отклонённое приглашение не создаёт обязательств.

**Fork канала:**
- Недовольный модерацией участник может взять полную историю (CRDT-состояние) и поднять свой Fruiting Gateway.
- Это как форк репозитория — новый канал с той же историей, но новым владельцем.

### 4.2. E2E шифрование

> ⚠️ **Иллюстративно, требует отдельной спецификации до реализации.** Детали и обоснование — MUSH-ARCH §3.

**Протокол:** one-way pattern Noise Framework (Noise_N/XK) или X3DH + pre-keys. Двухфазные handshake (Noise_XX, Noise_IK с обменом в реальном времени) в store-carry-forward недоступны: получатель офлайн, обмена «в обе стороны» нет.

**Почему не классический Signal Double Ratchet:**
- Классический Double Ratchet предполагает доставку цепочек через сервер. В DTN сервера нет.
- One-way pattern позволяет отправителю зашифровать сообщение, имея только публичный ключ получателя (и опубликованный one-time pre-key).

**Схема (иллюстративно):**
```
Отправитель:
  1. Получает pubkey получателя из ContactManager (+ pre-key, если X3DH).
  2. One-way handshake (Noise_N/XK) или X3DH → shared secret.
  3. Шифрует сообщение AEAD в рамках handshake — один AEAD-слой
     (AEAD протокола Noise ИЛИ AEAD приложения, не оба).
  4. Формирует bundle: encrypted_payload + служебные данные
     для восстановления сессии получателем.
  5. Передаёт в Mycerus для маршрутизации.

Получатель:
  1. Получает bundle из Mycerus.
  2. Восстанавливает shared secret по служебным данным (pre-key id,
     ephemeral pubkey).
  3. Расшифровывает payload.
  4. Показывает в чате.
```

**Forward secrecy:** каждое сообщение использует новый ephemeral ключ / msg_key из chain. Компрометация долговременного ключа не раскрывает прошлые сообщения.

### 4.3. Bundle формат для MUSH

> ⚠️ **Иллюстративно. Нормативный wire-формат MEB — MEB-SPEC v0.1.2 §4; Immune Block — ATTACK-MODEL v0.5.0 §6. Ниже — только то, что MUSH добавляет поверх.**

**MEB (тип 200)** — нормативный формат: **см. MEB-SPEC v0.1.2 §4**. MUSH не добавляет и не изменяет поля MEB. Реальные ключи верхнего уровня MEB (1–10): `version`, `genome_id` (CID генома Vironet), `genome_signature`, `mgr_hint`, `sns`, `sre`, `pot`, `expires_at`, `nonce`, `creator_signature`. Внутри `mgr_hint`: `destination_affinity`, `gradient_ttl`, `path_cost`, `visited`, `reason`; внутри `pot`: `copies_remaining`, `contact_priority`, `strategy_hint`, `contact_budget_ms`.

**MUSH Payload Block (тип 203)** — **зарезервирован, требует отдельной спецификации** (`payload_type` enum — предварительно: text, file, voice, group_invite, group_key_rotation). До принятия спецификации тип 203 не использовать в сети.

**Immune Block (тип 202)** — самостоятельный блок против **ключа узла** (см. ATTACK-MODEL v0.5.0 §6): subtype 1 = Threat (подписанное утверждение сенсора), 2 = Quarantine (приказ кворума), 3 = Revoke (отзыв ключа), 4 = Reroute (rerouting campaign). Сенсоры и кворум бьют **по ключу узла, не по payload**: сообщения не помечаются как «подозрительные» — санкции накладываются на узел-источник. Каркас блока 202 реализован (этап 18, ТЗ); полный протокол — этапы 19–22.

**Ключевое:** Mycerus видит только destination/source EID и routing policy (MEB). Он не видит содержимое сообщения, не знает, групповое это чат или личный, не знает тип media. Это обеспечивает metadata minimization в пределах §5.3.

### 4.4. Контакт-менеджер

```
Contact {
    pubkey: Ed25519PublicKey,     // идентификатор
    display_name: String,          // пользовательское имя
    identicon: Image,              // аватар на основе pubkey
    trust_level: enum {unknown, known, verified},
    added_at: Timestamp,
    last_seen: Option<Timestamp>,  // последний контакт через сеть
    // Нет телефона. Нет email. Нет username.
}
```

**Верификация:** пользователь может сравнить fingerprint ключа с собеседником при личной встрече (Safety Number, как в Signal). Если fingerprint совпадает — `trust_level = verified`, отображается зелёная галочка. Это же out-of-band сравнение закрывает MITM на первом контакте (см. MUSH-ARCH §3).

## 5. Как это работает в разных сценариях

> ⚠️ **Иллюстративно.** Маршрутизация — MGR-API-SPEC v0.2; требования к видимости destination в MEB — MEB-SPEC v0.1.2 §4.2.

### 5.1. Два человека в одной комнате

```
Алиса ──WiFi-Direct──▶ Боб

Время доставки: секунды
Mycerus: 1 hop, direct contact
Шифрование: E2E one-way pattern (см. §4.2)
```

### 5.2. Алиса в центре, Боб на окраине (нет прямого контакта)

```
Алиса ──WiFi──▶ Router1 ──mesh──▶ Router2 ──BLE──▶ Боб
     (home)       (grocery)        (cafe)        (work)

Время доставки: минуты–часы (пока сообщение "переползёт" по mesh)
Mycerus: store-carry-forward, gradient routing (MGR)
Пользователь видит: ⏳ → ✓✓
```

### 5.3. Интернет-отключение (протесты, катастрофы, цензура)

```
Алиса ──WiFi-Direct──▶ Телефон Веры ──BLE──▶ Телефон Глеба ──WiFi──▶ Боб
                                              (прохожий)      (кафе)

Время доставки: зависит от мобильности людей (минуты–дни)
Mycerus: epidemic/SnW routing, люди = курьеры
Конфиденциальность: посредник видит EID источника/назначения (pubkey),
                    размер и время передачи bundle'а.
                    Сокрытие метаданных (onion routing) — дорожная карта
                    (см. MUSH-ARCH §2.7), в текущей сети НЕ гарантируется.
```

### 5.4. Bridge в интернет (нормальная жизнь)

```
Алиса ──mesh──▶ Router ──Internet Bridge──▶ Интернет ──Bridge──▶ Router ──mesh──▶ Боб
         (Moscow)                                              (Berlin)

Время доставки: секунды
Mycerus: интернет используется как ещё один CLA (Channel Layer Adapter)
Конфиденциальность: bridge видит зашифрованные bundle'ы, но не содержимое.
                    Можно использовать Tor/I2P поверх bridge для metadata protection.
```

## 6. Конфиденциальность: откуда она берётся

> ⚠️ **Иллюстративно.** Иммунные механизмы — ATTACK-MODEL v0.5.0; сетевые сенсоры — этапы 19–22 (11 сенсоров сетевого уровня, ATTACK-MODEL §7; прикладные спам-сенсоры S1–S7 — ATTACK-MODEL §18).

| Угроза | Как MUSH защищается |
|--------|-------------------------|
| **Перехват сообщений** | E2E-шифрование (см. §4.2). Перехваченный bundle — это мусор без приватного ключа получателя. |
| **Анализ метаданных** | Частично: BPv7 source/destination — это EID (pubkey), не телефон/IP. Но посредник видит EID, размер и время (см. §5.3). Полное сокрытие метаданных (onion routing) — дорожная карта, в текущей сети не гарантируется. |
| **Центральный сервер** | Его нет. Нет сервера = нет серверных логов, subpoena, data breach. |
| **Correlation атаки** | Каждое сообщение — новый ephemeral ключ. Нет постоянного session ID. Bundle'ы перемешиваются в очередях узлов. |
| **Социальная инженерия / спам** | Нет публичного каталога. Контакт — только через QR/NFC + SBP-handshake. Спам структурно затруднён. Если прорывается — срабатывают прикладные спам-сенсоры S1–S7 (ATTACK-MODEL §18) и Immune plane (сетевые сенсоры, этапы 19–22). |
| **Физический анализ устройства** | Messages stored encrypted at rest (SQLCipher). Ключ защищён Keychain/Keystore. |
| **Сетевая изоляция (eclipse)** | Mycerus Immune plane (ATTACK-MODEL v0.5.0) детектирует и изолирует вредоносные узлы (этапы 19–22). |

**Plausible deniability (ограниченная):** relay-узел может сказать: "Я relay'ил зашифрованные bundle'ы, не знаю содержимого". Это правда, но он **знает** EID источника/назначения, размер и время — эти метаданные в текущей сети видимы (см. §5.3).

## 7. Как Mycerus усиливает MUSH

> ⚠️ **Иллюстративно.** Нормативные форматы — MEB-SPEC v0.1.2 / MGR-API-SPEC v0.2 / ATTACK-MODEL v0.5.0.

| Компонент Mycerus | Как это помогает MUSH |
|-------------------|---------------------------|
| **MEB (тип 200)** | Routing policy для сообщений: приоритет (pot.contact_priority), copies (pot.copies_remaining), gradient hints (mgr_hint). Срочные сообщения (SOS) получают высокий приоритет. Формат — MEB-SPEC v0.1.2 §4. |
| **MGR (градиенты)** | Автоматическая маршрутизация без конфигурации. Телефон сам находит лучший путь к получателю. Требует видимости destination_affinity/path_cost/visited (MEB-SPEC v0.1.2 §4.2) — сокрытие destination в текущем протоколе невозможно (открытый вопрос, см. MUSH-ARCH §2.1). |
| **SNS/SRE (Ed25519)** | Аутентификация **узлов** (challenge-response, ТЗ §9). MUSH не подключается к чужой точке доступа без прохождения узловой аутентификации. |
| **Vironet (геномы)** | Сеть адаптируется к условиям: в толпе — epidemic, в пустыне — spray-and-wait, в городе — gradient. Пользователь не замечает. |
| **Immune plane (тип 202)** | Защита от Sybil, false beacon, blackhole. Immune Block 202 — самостоятельный блок против ключа узла (Threat/Quarantine/Revoke/Reroute), инвариант «бьём по ключу, не по payload». Каркас реализован (этап 18, ТЗ); 11 сетевых сенсоров — этапы 19–19A; полный протокол ответа, attack harness и immune memory — этапы 20–22. |
| **Store-Carry-Forward** | Сообщение не пропадает, если получатель offline. Оно "плывёт" по сети, пока не дойдёт или не истечёт TTL. |

## 8. Модель монетизации (или её отсутствие)

**MUSH — open-source, некоммерческий проект.**

- Клиент — бесплатный, open-source (GPL/AGPL).
- Протокол — открыт (RFC-стиль).
- Грибница — разворачивается сообществами, организациями, муниципалитетами.
- Единственный возможный доход: поддержка enterprise-внедрений (корпоративные mesh-сети, муниципальные системы связи).

**Это не стартап.** Это инфраструктура, как TOR, как Bitcoin, как Mycelium (кошелёк). Сначала — полезность, потом — устойчивость.

## 9. Roadmap: от концепта к MVP

> Мобильные радиотранспорты и мобильные приложения — вне скоупа MVP Mycerus (ТЗ §3.2): MUSH-этапы — параллельный трек поверх готовой грибницы. Маппинг этапов — MUSH-ARCH §9. Демо-прототип A' — MUSH-A'-SPEC.md (вне скоупа MVP, ТЗ §3.2).

### Фаза 1. MUSH Lite (3 месяца)
- **Цель:** Два телефона переписываются по WiFi-Direct.
- **Стек:** React Native + Rust (via React Native Rust Bridge).
- **Фичи:**
  - Регистрация (ключ).
  - Добавление контакта по QR.
  - Текстовые сообщения E2E.
  - Статусы: отправлено / доставлено узлу (подписанная квитанция).
  - 1-to-1 чаты.
- **Mycerus:** Минимальная сборка (BPv7 + WiFi-Direct CLA + простая маршрутизация).
- **Без:** Immune plane, Vironet, групповые чаты, файлы.

### Фаза 2. MUSH Mesh (6 месяцев)
- **Цель:** Сообщение доходит через 3+ hop'а mesh-сети.
- **Фичи:**
  - BLE и LAN transport.
  - Групповые чаты.
  - Голосовые сообщения.
  - Вкладка "Сеть" (визуализация).
  - Relay-режим (добровольный).
- **Mycerus:** Полная интеграция MGR + SNS + POT.

### Фаза 3. MUSH Resilient (12 месяцев)
- **Цель:** Работает без интернета в городе с 1000+ узлами.
- **Фичи:**
  - Immune plane (ATTACK-MODEL v0.5.0 в продакшене; этапы 19–22).
  - Vironet (адаптивная маршрутизация).
  - Файлы и медиа.
  - Desktop/Web клиенты.
  - Интернет-bridge (опционально).
- **Тестирование:** SocioPatterns-трассы, стресс-тесты, аудит безопасности.

## 10. Почему это может сработать

| Фактор | Обоснование |
|--------|-------------|
| **Простота** | Пользователь видит мессенджер. Вся сложность спрятана. |
| **Уникальность** | Нет другого мессенджера, который работает без интернета через mesh. Briar есть, но он только для Android и не имеет DTN-оптимизации. |
| **Надёжность** | Store-carry-forward **повышает вероятность** доставки, но DTN доставку не гарантирует. Честные статусы: **отправлено / доставлено узлу или custodian'у (подписанная квитанция ReportE2EDelivery, MGR-API-SPEC §4.12) / истекло по TTL**. Не «отправлено» и не «прочитано» — факт прочтения человеком квитанция не подтверждает. |
| **Конфиденциальность** | No server, E2E by default, no phone number. Метаданные (EID, размер, время) видимы посреднику — сокрытие через onion routing в дорожной карте (§5.3). |
| **Иммунитет** | Mycerus защищён от атак на сеть — это не просто mesh, это mesh, который лечит сам себя (ATTACK-MODEL v0.5.0). |
| **Спам затруднён + иммунитет** | Нет глобального адресного пространства, нет публичных ID. Сообщение только после осознанного SBP-handshake. Если спам прорывается — прикладные сенсоры S1–S7 (ATTACK-MODEL §18) и Immune plane (этапы 19–22) детектируют аномалию и применяют точечную контрмеру по ключу узла. |
| **Биологическая метафора** | MUSH — запоминающееся, отличительное, "естественное" имя. Противопоставление "мёртвой" централизованной инфраструктуре и "живой" mesh-сети. |

## 11. Риски

| Риск | Митигация |
|------|-----------|
| **Батарея телефона** | BLE низкое энергопотребление. Relay-режим опционален. |
| **Скорость** | DTN медленнее IP. Позиционирование: "доставка вероятна", а не "мгновенная". |
| **Удобство** | QR/NFC для добавления контактов сложнее, чем "найти по номеру телефона". Компромисс: можно импортировать контакты из другого MUSH-устройства. |
| **Цензура приложения** | Google Play / App Store могут заблокировать. Решение: F-Droid, сайт с APK, PWA-версия. |
| **Группы требуют инфраструктуры** | Нет чужого сервера = хочешь канал, поднимай грибницу (Fruiting Gateway). Это требует ресурсов и ответственности. Компромисс: группы возможны, но требуют сознательного решения. Личные чаты работают без грибницы. |
| **Начальная сеть** | Первые пользователи не видят других узлов. Решение: bootstrap через известные публичные Mycerus-роутеры (как DHT bootstrap nodes). |
| **Ложные срабатывания иммунитета** | Критерий этапа 19: ложные тревоги < 5% без атаки; апелляции против verifiable quarantine (ATTACK-MODEL §13.2). |

---

*MUSH — это не просто мессенджер. Это интерфейс к живой сети. Пользователь берёт в руки ягоду, а за ней — целая грибница, которая думает, защищается и адаптируется.*
