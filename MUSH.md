## 1. Почему Mush

Mycerus — это инфраструктура: грибница из проводов, протоколов и иммунной системы. Для инженера это красиво. Для человека с телефоном — это "плесень".

**Mush** — это то, что растёт на грибнице: простой, сочный, понятный плод. Пользователь не знает про DTN, BPv7, Vironet или Immune Block. Он знает, что открыл приложение, написал сообщение, и оно дошло — даже если сейчас нет интернета, даже если собеседник в другом конце города, даже если кто-то глушит связь.

**Три столпа:**
1. **Простой** — как Telegram, но без сервера.
2. **Надёжный** — как почта, но быстрее.
3. **Конфиденциальный** — как личная встреча, но на расстоянии.

**Плодовые тела (Mush Client)** — телефоны, ноутбуки, планшеты. Они:
- Генерируют ключи (Ed25519) при первом запуске.
- Шифруют сообщения E2E перед отправкой.
- Подключаются к ближайшим узлам Mycerus через WiFi-Direct, BLE или LAN.
- Могут работать в режиме "только я" (consumption) или "я + relay" (добровольно раздают чужие сообщения).

**Грибница (Mycerus Mesh)** — статичные узлы: роутеры, одноплатники, WiFi-точки. Они:
- Формируют постоянную mesh-инфраструктуру.
- Хранят и пересылают bundle'ы (store-carry-forward).
- Выполняют маршрутизацию (MGR), аутентификацию (SNS) и иммунную защиту.
- Могут иметь bridge в интернет (опционально).

## 3. Пользовательский опыт (UX)

### 3.1. Первый запуск (30 секунд)

1. **Скачивание** — App Store, F-Droid, или ссылка от друга.
2. **Splash screen** — логотип Mush (ягода + мицелий).
3. **Генерация ключа** — "Создаём ваш защищённый ключ..." (2 секунды, Ed25519). Нет телефона, нет email, нет SMS.
4. **Имя и аватар** — отображаемое имя + автоматический идентикон на основе pubkey.
5. **Готово** — можно сразу получать invite или показать QR.

**Ключ — это ты.** Нет учётной записи, которую можно взломать. Нет сервера, который может утечь.

### 3.2. Добавление контакта

**Основной поток (invite-link):**

```
Алиса → "Поделиться контактом" → генерирует invite-link
        ↓
https://mush.app/i#pubkey=abc123&nonce=xyz789
        ↓
Боб кликает ссылку → открывается страница → скачивает приложение
        ↓
Приложение автоматически подхватывает pubkey Алисы + nonce
        ↓
SNS-handshake → контакт добавлен. Один клик, ноль ручного ввода.
```

Invite-link содержит:
- URL для скачивания (универсальная ссылка на APK / TestFlight / F-Droid)
- Pubkey приглашающего
- Ephemeral nonce для SNS-handshake

**Fallback для офлайн (QR / NFC):**

| Способ | Когда | Как работает |
|--------|-------|-------------|
| **QR-код** | Нет интернета, нельзя кликнуть ссылку | Алиса показывает QR с pubkey. Боб сканирует. SNS-handshake для подтверждения. |
| **NFC** | Телефоны рядом | Касаются → ключи передаются → SNS-handshake автоматически. |
| **Ретрансляция** | Есть общий контакт | Общий контакт C передаёт pubkey A к B (encrypted). B получает ключ, но **не может отправить сообщение** — нужен SNS-handshake с A. |

**Конфиденциальность:** публичный ключ не раскрывает личность. Никакого центрального каталога. Invite-link — это не публичный профиль, это одноразовый токен.

### 3.3. Чат

```
┌─────────────────────────────┐
│  ◀  Алиса        [⋯] [⚡]  │  ← имя контакта, статус сети
├─────────────────────────────┤
│                             │
│  Привет, как дела?          │  ← сообщение отправлено
│            ✓✓  14:32        │     ✓ = дошло до сети
│                             │     ✓✓ = получатель скачал
│                             │
│  Я в районе моста, связи    │  ← сообщение в пути
│  почти нет                  │     часы = ждём маршрут
│            ⏳               │
│                             │
│                Всё ок!      │  ← входящее
│                ✓✓  15:45    │
│                             │
├─────────────────────────────┤
│  [📎]  [🎤]  Написать... [▶]│
└─────────────────────────────┘
```

**Статусы сообщения:**
- `✓` — сообщение принято сетью Mycerus (есть хотя бы 1 путь).
- `✓✓` — сообщение доставлено получателю (его устройство скачало bundle).
- `⏳` — сообщение ожидает пути (нет контактов, но оно хранится и будет отправлено).
- `⚠️` — сеть подозревает атаку на маршрут (Immune plane сработал), возможна задержка.

**Никаких "онлайн" статусов.** В DTN понятие "онлайн" не имеет смысла. Вместо этого:
- "Был в сети X минут назад" (по последнему контакту).
- "Рядом N узлов" (сколько Mycerus-узлов видит ваш телефон прямо сейчас).

### 3.4. Сеть

Вкладка "Сеть" показывает абстрактную визуализацию:
```
        [🍄]           ← вы
       /  |  \
    [📡] [📡] [📱]     ← 3 узла в радиусе (2 роутера, 1 телефон)
      \   |   /
       [🌐]           ← internet bridge (опционально)

Сеть: 12 узлов видно
Путь к Алисе: 3 прыжка
Сообщения в очереди: 2
```

Это **не карта с координатами** — это абстрактный граф. Никакой геолокации, никакого отслеживания.

### 3.5. Групповые чаты — сервер-грибница (Fruiting Gateway)

В Mush нет "общего чата в воздухе". Хочешь канал — поднимай свою грибницу.

**Как это работает:**
- Создатель поднимает **Fruiting Gateway** — выделенный узел Mycerus (может быть на телефоне, роутере, Raspberry Pi).
- Грибница-хост хранит историю канала, relay'ит сообщения участникам.
- Участники синхронизируются при контакте с грибницей (store-carry-forward).
- Создатель модерирует relay, но не может подделать историю — сообщения подписаны отправителями.

**Приглашение:**
- Создатель отправляет invite (QR или через контакт).
- Участник **явно принимает** (accept) — без согласия нет подписки.
- Отклонённое приглашение не создаёт обязательств.

**Fork канала:**
- Недовольный модерацией участник может взять полную историю (CRDT-состояние) и поднять свой Fruiting Gateway.
- Это как форк репозитория — новый канал с той же историей, но новым владельцем.

### 4.2. E2E шифрование

**Протокол:** Noise Framework (Noise_XX или Noise_IK с Ed25519 static keys).

**Почему Noise, а не Signal:**
- Signal требует сервера для доставки pre-keys. В DTN сервера нет.
- Noise работает в однофазном handshake — подходит для store-carry-forward.
- Легковесный, понятный, проверенный.

**Схема:**
```
Отправитель:
  1. Получает pubkey получателя из ContactManager.
  2. Генерирует ephemeral ключ.
  3. Noise_XX handshake → shared secret.
  4. Шифрует сообщение: AES-256-GCM с shared secret.
  5. Формирует bundle: encrypted_payload + sender_pubkey + ephemeral_pubkey.
  6. Передаёт в Mycerus для маршрутизации.

Получатель:
  1. Получает bundle из Mycerus.
  2. Восстанавливает shared secret через Noise handshake.
  3. Расшифровывает payload.
  4. Показывает в чате.
```

**Forward secrecy:** каждое сообщение использует новый ephemeral ключ. Компрометация долговременного ключа не раскрывает прошлые сообщения.

### 4.3. Bundle формат для Mush

```
BPv7 Bundle
├── Primary Bundle Block
│   ├── destination: mush://<base64_pubkey>  (EID типа dtn)
│   ├── source: mush://<base64_pubkey>
│   ├── creation_timestamp: uint64
│   └── lifetime: uint64 (TTL сообщения, например 7 дней)
├── Mycerus Extension Block (MEB, тип 200)
│   └── routing_policy: {priority, spray_copies, gradient_hints}
├── Mush Payload Block (тип 203 — новый)
│   ├── version: 1
│   ├── payload_type: enum {text, file, voice, group_invite, group_key_rotation}
│   ├── encrypted_payload: bytes (Noise-encrypted)
│   ├── ephemeral_pubkey: bytes (Ed25519)
│   └── mac: bytes (HMAC-SHA256 для integrity)
└── Immune Block (тип 202, опционально)
    └── если сообщение помечено сенсором как подозрительное
```

**Ключевое:** Mycerus видит только destination/source EID и routing policy. Он не видит содержимое сообщения, не знает, групповое это чат или личный, не знает тип media. Это обеспечивает metadata minimization.

### 4.4. Контакт-менеджер

```
Contact {
    pubkey: Ed25519PublicKey,     // идентификатор
    display_name: String,          // пользовательское имя
    identicon: Image,              // аватар на основе pubkey
    trust_level: enum {unknown, known, verified},
    added_at: Timestamp,
    last_seen: Option<Timestamp>,  // последний контакт через сеть
    // Нет телефона. Нет email. Нет username.
}
```

**Верификация:** пользователь может сравнить fingerprint ключа с собеседником при личной встрече (Safety Number, как в Signal). Если fingerprint совпадает — `trust_level = verified`, отображается зелёная галочка.

## 5. Как это работает в разных сценариях

### 5.0. Ограничения платформы: сеть устройства

Ранее здесь было зафиксировано ограничение «вендорские прошивки (HyperOS, EMUI) блокируют входящий TCP к приложению — такое устройство может быть только клиентом». **Ревизия 14.10 (тест-план §3.5 п.19) опровергла его:** inbound-пробы по всему парку реальных устройств — POCO (HyperOS 3.0, MIUI 14), Huawei (EMUI 10), Xiaomi (MIUI 12, MIUI 8.1) — проходят штатно. Наблюдавшийся 13.10 «вендорский блок» был артефактом сетевой среды, прежде всего **VPN-приложения с `bypassable=false`** (весь трафик приложения уходит в VPN-туннель, входящие TCP к узлу не доходят — снаружи это выглядит как блокировка прошивкой).

**Что это значит для пользователя:** владельцем группы (тот, кто поднимает точку доступа и принимает входящие) может быть любое устройство из поддерживаемых. Два условия: (1) VPN на устройстве-владельце выключен или настроен с разрешением локальных сетей (bypass для LAN); (2) прошивка не блокирует локальный hotspot (у всех протестированных вендоров работает; встречавшиеся в сети жалобы касаются отдельных прошивок/операторов — тест-план §3.6, чеклист диагностики).

**Если группа не собирается:** проверьте, что у владельца выключен VPN и оба устройства в одной сети (один роутер или hotspot владельца); клиентская роль при этом не страдает никогда.

### 5.1. Два человека в одной комнате

```
Алиса ──WiFi-Direct──▶ Боб

Время доставки: секунды
Mycerus: 1 hop, direct contact
Шифрование: Noise_XX
```

### 5.2. Алиса в центре, Боб на окраине (нет прямого контакта)

```
Алиса ──WiFi──▶ Router1 ──mesh──▶ Router2 ──BLE──▶ Боб
     (home)       (grocery)        (cafe)        (work)

Время доставки: минуты–часы (пока сообщение "переползёт" по mesh)
Mycerus: store-carry-forward, gradient routing
Пользователь видит: ⏳ → ✓✓
```

### 5.3. Интернет-отключение (протесты, катастрофы, цензура)

```
Алиса ──WiFi-Direct──▶ Телефон Веры ──BLE──▶ Телефон Глеба ──WiFi──▶ Боб
                                              (прохожий)      (кафе)

Время доставки: зависит от мобильности людей (минуты–дни)
Mycerus: epidemic/SnW routing, люди = курьеры
Конфиденциальность: каждый посредник видит только зашифрованный bundle,
                    не знает отправителя/получателя (onion-like metadata)
```

### 5.4. Bridge в интернет (нормальная жизнь)

```
Алиса ──mesh──▶ Router ──Internet Bridge──▶ Интернет ──Bridge──▶ Router ──mesh──▶ Боб
         (Moscow)                                              (Berlin)

Время доставки: секунды
Mycerus: интернет используется как ещё один CLA (Channel Layer Adapter)
Конфиденциальность: bridge видит зашифрованные bundle'ы, но не содержимое.
                    Можно использовать Tor/I2P поверх bridge для metadata protection.
```

## 6. Конфиденциальность: откуда она берётся

| Угроза | Как Mush защищается |
|--------|-------------------------|
| **Перехват сообщений** | E2E Noise-шифрование. Перехваченный bundle — это мусор без приватного ключа получателя. |
| **Анализ метаданных** | BPv7 source/destination — это EID (pubkey). Relay-узлы не знают, кто реальный человек за ключом. Bundle не содержит телефона, IP, геолокации. |
| **Центральный сервер** | Его нет. Нет сервера = нет серверных логов, subpoena, data breach. |
| **Correlation атаки** | Каждое сообщение — новый ephemeral ключ. Нет постоянного session ID. Bundle'ы перемешиваются в очередях узлов. |
| **Социальная инженерия / спам** | Нет публичного каталога. Контакт — только через QR/NFC + SNS-handshake. Спам структурно затруднён. Если прорывается — срабатывает Immune plane (аномалия fan-out, поведенческий baseline). |
| **Физический анализ устройства** | Messages stored encrypted at rest (SQLCipher). Ключ защищён Keychain/Keystore. |
| **Сетевая изоляция (eclipse)** | Mycerus Immune plane (ATTACK-MODEL v0.3.0) детектирует и изолирует вредоносные узлы. |

**Plausible deniability:** любой узел mesh может сказать: "Я просто relay'ил зашифрованные bundle'ы. Я не знаю, что внутри, я не знаю, кто отправитель и получатель."

## 7. Как Mycerus усиливает Mush

| Компонент Mycerus | Как это помогает Mush |
|-------------------|---------------------------|
| **MEB (тип 200)** | Routing policy для сообщений: приоритет, copies, gradient hints. Срочные сообщения (SOS) получают высокий приоритет. |
| **MGR (градиенты)** | Автоматическая маршрутизация без конфигурации. Телефон сам находит лучший путь к получателю. |
| **SNS/SRE (Ed25519)** | Аутентификация узлов. Mush не подключается к вредоносной точке доступа — SNS отсеивает чужих. |
| **Vironet (геномы)** | Сеть адаптируется к условиям: в толпе — epidemic, в пустыне — spray-and-wait, в городе — gradient. Пользователь не замечает. |
| **Immune plane (тип 202)** | Защита от Sybil, false beacon, blackhole. Злоумышленник не может подменить сеть фальшивыми узлами и перехватить трафик. |
| **Store-Carry-Forward** | Сообщение не пропадает, если получатель offline. Оно "плывёт" по сети, пока не дойдёт. |

## 8. Модель монетизации (или её отсутствие)

**Mush — open-source, некоммерческий проект.**

- Клиент — бесплатный, open-source (GPL/AGPL).
- Протокол — открыт (RFC-стиль).
- Грибница — разворачивается сообществами, организациями, муниципалитетами.
- Единственный возможный доход: поддержка enterprise-внедрений (корпоративные mesh-сети, муниципальные системы связи).

**Это не стартап.** Это инфраструктура, как TOR, как Bitcoin, как Mycelium (кошелёк). Сначала — полезность, потом — устойчивость.

## 9. Roadmap: от концепта к MVP

### Фаза 1. Mush Lite (3 месяца)
- **Цель:** Два телефона переписываются по WiFi-Direct.
- **Стек:** React Native + Rust (via React Native Rust Bridge).
- **Фичи:**
  - Регистрация (ключ).
  - Добавление контакта по QR.
  - Текстовые сообщения E2E.
  - Статусы: отправлено / доставлено.
  - 1-to-1 чаты.
- **Mycerus:** Минимальная сборка (BPv7 + WiFi-Direct CLA + простая маршрутизация).
- **Без:** Immune plane, Vironet, групповые чаты, файлы.

### Фаза 2. Mush Mesh (6 месяцев)
- **Цель:** Сообщение доходит через 3+ hop'а mesh-сети.
- **Фичи:**
  - BLE и LAN transport.
  - Групповые чаты.
  - Голосовые сообщения.
  - Вкладка "Сеть" (визуализация).
  - Relay-режим (добровольный).
- **Mycerus:** Полная интеграция MGR + SNS + POT.

### Фаза 3. Mush Resilient (12 месяцев)
- **Цель:** Работает без интернета в городе с 1000+ узлами.
- **Фичи:**
  - Immune plane (ATTACK-MODEL v0.3.0 в продакшене).
  - Vironet (адаптивная маршрутизация).
  - Файлы и медиа.
  - Desktop/Web клиенты.
  - Интернет-bridge (опционально).
- **Тестирование:** SocioPatterns-трассы, стресс-тесты, аудит безопасности.

## 10. Почему это может сработать

| Фактор | Обоснование |
|--------|-------------|
| **Простота** | Пользователь видит мессенджер. Вся сложность спрятана. |
| **Уникальность** | Нет другого мессенджера, который работает без интернета через mesh. Briar есть, но он только для Android и не имеет DTN-оптимизации. |
| **Надёжность** | Store-carry-forward гарантирует доставку. Не "отправлено", а "будет доставлено". |
| **Конфиденциальность** | No server, no metadata, E2E by default, no phone number. |
| **Иммунитет** | Mycerus защищён от атак на сеть — это не просто mesh, это mesh, который лечит сам себя. |
| **Спам затруднён + иммунитет** | Нет глобального адресного пространства, нет публичных ID. Сообщение только после осознанного SNS-handshake. Если спам прорывается — Immune plane детектирует аномалию (fan-out, поведение) и применяет точечную контрмеру. |
| **Биологическая метафора** | Mush — запоминающееся, отличительное, "естественное" имя. Противопоставление "мёртвой" централизованной инфраструктуре и "живой" mesh-сети. |

## 11. Риски

| Риск | Митигация |
|------|-----------|
| **Батарея телефона** | BLE низкое энергопотребление. Relay-режим опционален. |
| **Скорость** | DTN медленнее IP. Позиционирование: "доставка гарантирована", а не "мгновенная". |
| **Удобство** | QR/NFC для добавления контактов сложнее, чем "найти по номеру телефона". Компромисс: можно импортировать контакты из другого Mush-устройства. |
| **Цензура приложения** | Google Play / App Store могут заблокировать. Решение: F-Droid, сайт с APK, PWA-версия. |
| **Группы требуют инфраструктуры** | Нет чужого сервера = хочешь канал, поднимай грибницу (Fruiting Gateway). Это требует ресурсов и ответственности. | Компромисс: группы возможны, но требуют сознательного решения. Личные чаты работают без грибницы. |
| **Начальная сеть** | Первые пользователи не видят других узлов. Решение: bootstrap через известные публичные Mycerus-роутеры (как DHT bootstrap nodes). |

---

*Mush — это не просто мессенджер. Это интерфейс к живой сети. Пользователь берёт в руки ягоду, а за ней — целая грибница, которая думает, защищается и адаптируется.*
